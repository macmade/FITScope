Per-Channel Auto-STF — Source Brief

2026-07-11  ·  Follows the completed 2026-07-04-stf-stretch initiative.

Problem

The auto Screen Transfer is uniform (linked): it derives one shadows / midtones pair from the single-channel luminance detectionImage and applies it to every colour channel. On a colour-imbalanced frame the single shadow clip — appropriate for luminance — lands above the dimmest channel's background and crushes it to black.

Measured on the real Seestar S30 M42 light-pollution sub (rendered through the app's pipeline), the auto-STF clips to pure black:

ChannelClipped to black (bin 0)
Red41%
Green6%
Blue4%

(Unstretched min/max clips ~0%.) A good stretch should clip only the darkest ~1–3% of each channel. The fix is an unlinked (per-channel) auto-STF, where each channel derives and applies its own shadows / midtones — the standard PixInsight behaviour for colour.

Why it was uniform (and why that no longer blocks us)

The completed STF plan deferred per-channel Auto for a pragmatic reason (Milestone 6): the post-debayer RGB buffer exists only transiently at render time, and per-channel Auto seemed to need a new SwiftPixel pass to expose it, so the uniform luminance derivation shipped instead.

That obstacle is avoidable: the loaders already retain the raw mosaic / planes. Per-channel statistics can come from deinterleaving the CFA mosaic by BAYERPAT (or from the RGB planes directly) — no render-time buffer required. And the per-channel apply path and parameter type (STFParameters.perChannel, Channel.computed(median:mad:…), computed(from:) for a 3-channel buffer) were all built in Milestone 1, so this is a derivation-input and plumbing change, not new stretch maths.

Agreed design

  • Per-channel is the default for colour; uniform stays the default for mono and remains a manual option (the STF editor's uniform ↔ per-channel toggle).
  • One shared derivation, applied everywhere. Opening a file, the inspector's one-click Auto, the STF editor window's Auto, and the QuickLook / Finder previews all route through the same derivation, so open == click-Auto stays true.
  • The inspector Auto produces per-channel for colour — required, not optional, to keep open and Auto in agreement.
  • The STF window's Auto respects the window's per-channel toggle: it fills whatever mode is active (per-channel mode → three channels; uniform mode → one). This gives a power user a colour-preserving uniform Auto on demand.
  • Keep uniform (linked) as an option. Mono has no other choice, linked STF preserves the true colour ratios (PixInsight ships both), and it already exists as the manual toggle.
  • Accepted consequence: a per-channel default neutralizes background colour casts on open (each channel's background independently lifted to the target) — effectively an automatic background colour balance. This is desirable and matches PixInsight's unlinked default, but is a real appearance change from today's uniform default.
