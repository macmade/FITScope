Improvements

Generated 2026-07-11 · Updated 2026-07-12

A collection of improvements for FITScope, gathered as they come up.

Backlog

1

Offer FITS as an export format

SwiftFITS will gain the ability to write FITS files. Once it does, expose a FITS option when exporting an image, so users can save to FITS as well. The option should be offered for every source except files that are already FITS, where re-exporting to the same format adds nothing.

2

Upload a FITS file for plate-solving XISF images

When submitting a file for plate-solving, non-FITS sources are currently uploaded as a PNG. For XISF images we could instead generate a FITS file carrying the correct metadata. Providing that metadata to nova.astrometry.net would most likely speed up the solve, since it would no longer be a blind solve when the relevant information is available.

3

Simplify XISF embedded FITS keyword handling

To parse the FITS keywords embedded in XISF files, we currently build FITS cards by hand. This approach is imperfect — particularly around padding. With the new SwiftFITS write capabilities, this handling could be simplified and made more robust.

4

Show star measurement labels in the stars overlay

Display a measurement label next to each detected star in the stars overlay. The metric should be selectable from the Overlay preferences — None, HFR, or FWHM — defaulting to HFR.

5

Fix the brightness and contrast adjustments

The brightness and contrast adjustments currently behave incorrectly — the result looks off, and the controls may be far too sensitive. In their present state they are not usable. Investigate the cause and rework them so they respond in a controlled, predictable way. As part of this, we should also consider moving the brightness and contrast adjustment to after the STF stretch in the processing pipeline.

6

Show real pixels when zoomed in

Investigate rendering the actual pixels (crisp, nearest-neighbor magnification) when zooming into the image, instead of the current smooth, interpolated rendering. This would let users inspect individual pixels at high zoom levels.

7

Silence the CFPrefs app-group warning at startup

A warning is logged to the console when the app starts: Couldn't read values in CFPrefsPlistSource<0x…> (Domain: group.com.xs-labs.FITScope, User: kCFPreferencesAnyUser, ByHost: Yes, Container: (null), Contents Need Refresh: Yes): Using kCFPreferencesAnyUser with a container is only allowed for System Containers, detaching from cfprefsd. It stems from accessing the group.com.xs-labs.FITScope app group shared with the Preview and Thumbnail extensions. Investigate the cause and eliminate the warning.

8

Only list open windows in the Window menu

The Window menu in the menu bar currently lists every available window — About, Levels, Curves, and so on — even when those windows are not open. Windows that have not been opened should not appear there; only the windows that are actually open should be listed.

9

Investigate and fix additional debug-console warnings

Several warnings are logged to the Xcode debug console when running the app. Investigate each one and fix it where possible:

  • Unable to obtain a task name port right for pid 420: (os/kern) failure (0x5)
  • Failed to locate resource named "default.csv"
  • CAMetalLayer ignoring invalid setDrawableSize width=0.000000 height=0.000000
  • clip: empty path.
