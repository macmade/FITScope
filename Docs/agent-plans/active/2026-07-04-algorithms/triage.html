Overview

This consolidates the 69 findings from the SwiftPixel (M2) and SwiftAstro (M3) audits into a single prioritized plan, merges the two cross-submodule themes, and maps every finding to one of 17 Phase-2 fix milestones (M5.1–M5.17). Nothing is deferred; the full-coverage index at the end lists all 69 findings against their milestone so none is lost.

Each fix milestone is scoped to a coherent subsystem within a single submodule (so each stays independently reviewable and committable), follows the plan's per-fix template (add a failing test, implement, keep the Xcode project and Package.swift in sync, run the suite green, re-run the M1 benchmark), and will be implemented one at a time in Phase 2 with the usual pause-and-review. Nine findings hinge on a decision the maintainer must make (below) — those milestones carry the decision and a recommendation, to be resolved before that milestone is implemented.

Cross-submodule themes (de-duplicated)

  • Non-finite (NaN/Inf) handling. Five findings share one root — float-FITS blank pixels are never sanitized: SwiftPixel BUG-1 (Normalize), CR-3 (GaussianKernel crash), CR-8 (median/percentileBounds), CR-9 (CosmeticCorrection); SwiftAstro CR-2 (SNR/sky background). One policy decision (D1) drives two milestones (M5.1 SwiftPixel, M5.12 SwiftAstro) applying it consistently.
  • The Bayer .rgbg/GBRG tangle. SwiftPixel CR-1 (.rgbg is not a valid CFA and demosaics wrong) and SwiftAstro BUG-1 (the FITS decoder omits the valid GBRG and maps RGBG into that broken path) are two ends of one problem. One decision (D2) drives two coordinated milestones (M5.2, M5.11).

Decision  Decisions from the maintainer

Each drives one or more fix milestones. All nine were resolved on 2026-07-16 (recorded in the plan's M4 Review comments); the per-decision detail below is retained for reference.

  • D1 — Filter: sanitize non-finite in the stat helpers + guard Normalize/GaussianKernel.
  • D2 — Remove RGBG, add GBRG.
  • D3 — Normalize the MAD (MADN, ×1.4826) for PixInsight parity.
  • D4 — Keep the lower-median and document.
  • D5 — Skip alpha and document.
  • D6 — True VNG: implement like-coloured gradients and same-colour-only borders.
  • D7 — True HFR matching NINA (flux-weighted mean radius, HFD/2); FWHM to the geometric mean across both paths.
  • D8 — Keep whole-image MAD and document.
  • D9 — Horizon: document + add a refraction-aware variant. Outer planets: add Schlyter's ~17 perturbation terms (also closes CR-9).

D1 · Non-finite (NaN/Inf) handling policy  → M5.1, M5.12

Float FITS frames carry NaN blanks. Options: (a) reject non-finite input with a thrown error; (b) filter non-finite samples inside each statistic (median/MAD/min/max) and guard the value transforms (Normalize, GaussianKernel); (c) mask/replace blanks at decode with a sentinel.

Recommendation: (b) — filter in the statistical helpers and add finiteness guards to Normalize/GaussianKernel, so a stray blank degrades gracefully instead of corrupting or crashing. Cheap, local, and preserves valid data.

D2 · Fate of the .rgbg pattern  → M5.2, M5.11

.rgbg (R,G/B,G) is not a real Bayer CFA. Options: (a) remove .rgbg from SwiftPixel's Pattern enum and the FITS decoder, and add the valid .gbrg; (b) keep .rgbg as an explicitly-documented non-Bayer path with its own handling.

Recommendation: (a) — remove .rgbg, add GBRG. It is not a pattern capture software emits, and keeping it only preserves a broken demosaic.

D3 · STF shadow clip — raw MAD vs normalized MAD  → M5.4

The Screen Transfer clips shadows with raw MAD, but its cited PixInsight −2.8 assumes normalized MAD (×1.4826). Options: (a) normalize the MAD for true PixInsight parity (deeper clip); (b) keep raw MAD and correct the docs to stop claiming parity.

Recommendation: (a) — normalize, so the result matches the algorithm the code says it implements (and the constant SwiftPixel already uses in CosmeticCorrection).

D4 · Histogram median convention  → M5.5

HistogramStatistics.median is the lower-median bin (first bin reaching half the count), biased low vs an interpolated median. Options: (a) keep the (documented, Int-typed) lower-median; (b) interpolate.

Recommendation: (a) — keep and document; it is deliberate and bin-indexed. (The genuine bug in the same file — small-total percentiles collapsing to bin 0 — is fixed regardless.)

D5 · Alpha handling & per-channel normalize  → M5.7

Invert/BrightnessContrast/CorrectGamma transform a 4th (alpha) channel; Normalize stretches globally across channels. Options: (a) skip alpha in those stages and document global normalization as intended; (b) add a per-channel normalize option and/or reject >3-channel input.

Recommendation: (a) — skip alpha where RGBA is reachable, document global normalize as the intended colour-preserving behaviour. Add per-channel only if a consumer needs it.

D6 · VNG fidelity & demosaic edges  → M5.8

VNG gradients mix unlike-coloured samples (not true Chang/Cok); border pixels edge-replicate wrong-colour neighbours. Options: (a) implement true like-coloured gradients and same-colour-only border handling; (b) relabel the mode “VNG-style” and document the border trade-off (both are locked by golden tests and low-impact for detection).

Recommendation: (b) unless demosaic image quality is a priority — the constants are correct and the current output is reasonable; honest labelling is the cheap, safe fix. Choose (a) if visual demosaic quality matters.

D7 · Star metrics — HFR meaning & FWHM basis  → M5.13

HFR: the code reports the half-light (encircled-50%) radius, not the flux-weighted-mean radius acquisition software (NINA/SGP/Ekos) calls “HFR” (+6.4% offset). Options: (a) keep the half-light radius but rename/clarify; (b) switch to the flux-weighted mean for interop.
FWHM: the one-number FWHM is the RMS of the two axis widths on the moment path but the geometric mean on the fit path. Pick one: RMS everywhere, or geometric mean everywhere.

Recommendation: HFR — your call (you flagged it): choose (b) if matching acquisition-software HFR matters to your users, (a) if the principled SExtractor radius is fine (then just fix the naming/test rationale). FWHM — geometric mean everywhere (the standard “equivalent circular” seeing FWHM).

D8 · SNR noise estimator  → M5.16

SNR/sky-background noise is whole-image 1.4826·MAD; PixInsight's SNRWeight uses a multiscale (MRS) estimate that excludes structure. Also, demosaicing biases CFA absolute noise low. Options: (a) keep the whole-image MAD (agrees with the star detector's estimator) and document the divergence + the CFA bias; (b) estimate noise on a high-pass residual for closer MRS parity.

Recommendation: (a) — document. The estimator is intentionally shared with the detector, and SNRWeight is a relative measure; MRS parity is a larger change for marginal benefit here.

D9 · Horizon convention & outer-planet accuracy  → M5.17

Horizon: isAboveHorizon uses 0°, twilight uses −0.833°, so the Sun can be “past sunrise” yet isAboveHorizon == false. Options: (a) document the distinction (and optionally add isAboveHorizon(refraction:)); (b) unify on the refraction-aware threshold.
Outer planets: mutual perturbations omitted (Saturn ~0.8°). Options: (a) keep & document (already honest); (b) add Schlyter's perturbation terms.

Recommendation: Horizon — (a) document + add the refraction-aware variant. Outer planets — (a) keep & document; it is ample for the visibility purpose. Choose (b) only if sub-0.1° outer-planet positions are wanted.

Phase-2 fix milestones

Ordered SwiftPixel first, then SwiftAstro; within each, roughly by severity. Decision marks a milestone gated on a decision above.

SwiftPixel

M5.1 Non-finite (NaN/Inf) sample handling Bug D1

Stop NaN/Inf blanks from corrupting or crashing: fix Normalize (the guard that misses NaN), guard GaussianKernel(sigma:) against non-finite σ, and define NaN order for median/percentileBounds and CosmeticCorrection's neighbour sort.

Covers: SP BUG-1, CR-3, CR-8, CR-9.

M5.2 Debayer .rgbg pattern Correctness-risk D2

Resolve the invalid .rgbg CFA (remove it, or give it a documented non-Bayer path), coordinated with M5.11.

Covers: SP CR-1.

M5.3 Channel-count guard order Correctness-risk

Reorder the guards in MonoToRGB and Debayer so a multi-channel buffer reports the accurate unsupportedChannelCount instead of a misleading dataSizeMismatch; fix the tests that pass on the wrong path.

Covers: SP CR-4, CR-5.

M5.4 Screen Transfer Function (STF) Correctness-risk D3

Resolve the raw-MAD-vs-MADN shadow clip (D3), and handle the degenerate median ≤ shadows case (median-0 frames) so the stretch doesn't collapse to a hard threshold.

Covers: SP CR-2, CR-10.

M5.5 HistogramStatistics small-sample robustness Correctness-risk D4

Fix the percentiles/median collapsing to bin 0 for total < 100 (clamp the thresholds); decide the lower-median convention (D4).

Covers: SP CR-7, CR-17 (lower-median).

M5.6 Public-API precondition validation Correctness-risk

Validate/guard the unenforced public entry points: Convolution.convolve and zeroSumResponse (sizes/channels), Curves.value(at:) (malformed curve), GaussianFit's absolute singularity threshold, BitsPerPixel.size overflow, and pin the 4-channel premultiplied-alpha contract with a test.

Covers: SP CR-11, CR-12, CR-13, CR-14, CR-15, IMP-7.

M5.7 Pipeline & processor semantics Improvement D5

Alpha handling and per-channel normalize (D5); validate Levels output inversion; no-op correctGamma:1.0 forcing auto-normalization; binFactor ignored/unvalidated for .rgb; document the MonoToRGB non-normalized requirement, the Scale flag clearing, and the Bin CFA-only assumption.

Covers: SP IMP-2, IMP-3, IMP-4, IMP-5, IMP-9, IMP-10, CR-17 (alpha, Bin).

M5.8 Demosaic quality (VNG gradients & edges) Improvement D6

VNG like-coloured gradients vs relabel, and the border edge-replicate contamination (D6).

Covers: SP IMP-1, CR-17 (Debayer edges).

M5.9 Test-coverage hardening Improvement

Close the audited-but-untested holes: fix the mis-wired invalidNormalize test; add a rotated/elliptical + noisy GaussianFit recovery test; Bin/Resample pipeline-integration tests; a Convolution output-edge regression test; PixelBuffer Equatable/throwing-body and the colour (ColorBalance/WhiteBalance/Hue/Saturation) assertions; and an external-value GaussianFit model check.

Covers: SP CR-6, CR-16, IMP-6, IMP-8, IMP-11, COS-7.

M5.10 Docs, cosmetics & minor cleanups Cosmetic

The vDSP_mmovD comment M/N swap; the stale GaussianFit “finite-difference Jacobian” docstrings; luma-vs-luminance naming; the redundant mtf branch; readRawPixels zero-sample return; Bin.outputSize for a rejected factor; the Deinterleave “must be positive” doc; and the unused Histogram bin arrays.

Covers: SP COS-1, COS-2, COS-3, COS-4, COS-5, COS-6, COS-8, IMP-12.

SwiftAstro

M5.11 FITS Bayer pattern support (GBRG) Bug D2

Add the valid GBRG mapping the decoder is missing, and resolve the RGBG mapping in step with M5.2 (D2). Add decoder Bayer-pattern tests.

Covers: SA BUG-1.

M5.12 Non-finite handling (SNR & sky background) Correctness-risk D1

Apply the D1 policy to SignalToNoise and SkyBackground so a float-FITS blank no longer yields NaN stats or discards a good frame.

Covers: SA CR-2.

M5.13 Star-metric conventions Correctness-risk D7

Resolve the HFR meaning and the FWHM basis (D7); apply the chosen FWHM consistently across the moment and fit paths; clamp eccentricity to [0,1]; report the roundness-gated eccentricity; tidy the half-flux dead branch and the bright-pass comparability doc.

Covers: SA CR-3, CR-4, CR-5, IMP-1, COS-3, COS-6.

M5.14 Detector config, robustness & performance Correctness-risk

Reconcile saturationLevel with the default-on bright pass; bound the sampleWidth fit window; give footprintWidth the annulus-sky read (or note the backstop); and add the missing config-knob / bright-threshold / SyntheticStarGrid recall tests.

Covers: SA CR-6, IMP-5, IMP-6, IMP-12, COS-8, COS-9.

M5.15 FITS decoder robustness Correctness-risk

Reject (or handle) NAXIS ≥ 3 cubes instead of silently truncating to plane 1; read the header once (drop the double data-segment materialization); mask integer BLANK pixels.

Covers: SA CR-1, IMP-2, IMP-3.

M5.16 SNR / sky-background estimator Improvement D8

Document (or refine) the whole-image-MAD noise estimator and the CFA smoothing bias (D8); validate SignalToNoise.init(noise:); de-duplicate the 1.4826 constant; tidy the channels-stride//3 mix in the grayscale combine.

Covers: SA CR-8, IMP-4, IMP-7, COS-1, COS-2.

M5.17 Ephemeris (conventions, coverage, cleanups) Improvement D9

Horizon convention and outer-planet accuracy (D9); add Jupiter/Saturn numeric position tests, an Ephemeris-facade test, and the moment-seed test; de-tautologize the isAboveHorizon tests; guard the zenith asin; note the e ≥ 1 Kepler limit; align the stray =.

Covers: SA CR-7, CR-9, IMP-8, IMP-9, IMP-10, IMP-11, COS-4, COS-5, COS-7.
