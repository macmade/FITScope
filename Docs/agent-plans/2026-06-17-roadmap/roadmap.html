FITScope — Roadmap

Generated: 2026-06-17

Issues and features are in no particular order, but issues should be addressed before adding new features. Optimization points should be done last, when everything else is stable.

1 — Tests

The project contains a unit test target (FITScopeTests) and a UI test target (FITScopeUITests). There are currently almost no UI tests. Evaluate whether such UI tests are needed and could be beneficial for development, especially with an AI agent. If so, implement the UI tests for the existing project. This should come first.

2 — Fixes

  • When opening a new window with an image, resizing the window is glitchy until the image is rendered — the left and right sidebars can clip.
  • When an image fits the window, it should keep fitting when the window is resized (larger or smaller).
  • If an image fits completely, disable zooming out.
  • For files with warnings (unable to render), add an attention icon to the right in the list view.
  • The loading status doesn't update in the list view when a non-displayed image is rendered — it only updates its status when clicked and displayed. Also, maybe related, rendering never ends or updates when opening the same image twice in the same window.
  • When re-rendering, loading should occur — spinning indicator in sidebar, status change in the bottom toolbar (ready/processing). Controls should be disabled in the inspector panel. Maybe add a dark overlay with a spinning indicator over the image.
  • The message text should be centered in the error view.
  • Checkboxes (original, channels, statistics) take a lot of space below the histogram. — Use another form of control for these options.
  • Invert should use a switch instead of a checkbox, as for gamma.
  • Review toolbar tooltips inconsistencies: "Toggle the inspector" vs "Hide Sidebar" / "Show Sidebar".
  • Tooltips should be added on all buttons in the top floating toolbar, in all inspector controls, and in the file list (maybe file path).
  • The about window should always be centered when shown, unless already shown.
  • Don't wrap text in histogram statistics.
  • There is currently no mono support for the histogram — it's always in RGB mode.

3 — New features

3.1 — Astro

  • Detect stars and compute FWHM, HFR, and eccentricity.
  • Show detected stars with an overlay on the image. Toggle from the top floating toolbar if stars were detected.
  • Plate solve via nova.astrometry.net (an API key is needed, see the point about preferences later). Could open a new window with plate-solving results.
  • Show objects if available in the plate solving with an overlay on the image. Toggle from the top floating toolbar if objects are present.
  • Measurements overlay on the image, if enough info is available (like a degree bar, using pixel scale, focal length, etc., bottom right).
  • Center reticle overlay. Toggle from the top floating toolbar.
  • Show similar images on Astrobin, using coordinates if available and if we can use a GET request on Astrobin. Could be in the files list context menu and/or in the top floating toolbar.
  • If it can be computed, add sampling info in the information panel and detect under/over-sampling.
  • If GPS coordinates are available, add an Apple Maps view. Same place as the info panel; could use tabs.
  • If the date is available and if it can be computed or retrieved using an external public API, add a Moon phase view. Same place as the info panel; could use tabs. It should also be displayed in the info panel with an icon.
  • If GPS coordinates and date are available, add a weather conditions view. Same place as the info panel; could use tabs. It should also be displayed in the info panel with an icon. Could use OpenWeatherMap with an API key (see the point about preferences later).
  • If GPS coordinates are available, add the Bortle scale to the info panel if it can be retrieved with an external public API.
  • If enough info is available, show north as an overlay on the image (top right). Toggle from the top floating toolbar.
  • Export FITS headers to TSV or CSV from the FITS headers window.
  • Allow entering a weight formula in the preferences window with placeholders (for FWHM, HFR, eccentricity). Validates the formula.
  • Compute weight using the formula if available.
  • Allow sorting of images in the list view by name, FWHM, HFR, eccentricity, weight, etc.
  • If RA/DEC and pixel scale are available, add an equatorial grid overlay on the image. Toggle from the top floating toolbar.
  • Recommend other useful features for astrophotography, if any.

3.2 — Processing

  • Add a logarithmic option to the histogram if useful.
  • Rotate and flip the image from the top floating toolbar or inspector panel. Processing code should be added in the SwiftPixel submodule.
  • Brightness and contrast controls in the inspector panel. Processing code should be added in the SwiftPixel submodule.
  • Saturation control in the inspector panel. Processing code should be added in the SwiftPixel submodule.
  • Curves adjustment tool. Maybe as a button in the inspector panel that opens a new window. Processing code should be added in the SwiftPixel submodule.
  • Levels adjustment tool. Maybe as a button in the inspector panel that opens a new window. Processing code should be added in the SwiftPixel submodule.

3.3 — File handling

  • Check whether the current implementation and pixel pipeline could support other file types, such as JPEG, TIFF, PNG, HEIC, RAW (Canon, Apple, etc), using Apple image frameworks such as CoreGraphics or ImageIO.
  • Evaluates support for XISF files if the format is documented and not too complex. This would require a dedicated submodule — only evaluation for now.
  • In the files list context menu, add "Reveal in Finder", "Move to Trash", "Open in new window".
  • Evaluate support for files with NAXIS=1. Propose a solution, maybe displaying a graph with SwiftCharts? If too complex, evaluate and propose — this could be part of another plan.
  • Evaluate support for files with NAXIS=3. If too complex, evaluate and propose — this could be part of another plan.
  • Evaluate support for files with NAXIS>=3. If too complex, evaluate and propose — this could be part of another plan.
  • When clicking on the filename in the window's toolbar, display a dropdown menu with the folder hierarchy, opening the Finder when selected.
  • Add a QuickLook plugin for displaying FITS files in the Finder (no processing).
  • Add "Save as" in the main menu and in the files list context menu (copy the original FITS file).
  • Add "Export" to the main menu and to the files list context menu. Save as TIFF, PNG, or JPEG (with compression level).
  • Add a "Share" button somewhere (main window's toolbar?) using Apple's Share menu. Use JPEG with some level of compression, like maybe 90%.

3.4 — Miscellaneous

  • Redesign the FITS header window to make it look nicer. The search field is currently not very visible.
  • Add "Check for Updates" in the application's menu (using GitHubUpdater from SwiftUtilities).
  • Add a Preferences window (required by some milestone) — enter API keys, choose info panel values and order.

4 — Miscellaneous

  • Improve the README file, making it more commercial, with placeholders for screenshots.

5 — Optimization

  • Review all algorithms in SwiftPixel — verify current implementations, suggest new implementations or algorithms, check if some existing ones don't make sense.
  • Optimize algorithms in SwiftPixel using Metal kernels.
