Bugs

Generated 2026-06-28 · Updated 2026-06-28

A working list of known bugs and open design questions in FITScope. It tracks concrete defects to fix as well as a couple of unresolved questions about how image stretching should interact with star detection and preview generation.

Roadmap

  1. Thumbnail extension shows white borders

    The Finder thumbnail rendered by the thumbnail extension (FITScopeThumbnailExtension) has unwanted white borders along the top and right edges. The rendered image should fill its bounds cleanly, without these stray margins.

  2. Warn when no stars are detected

    When star detection finds no stars, the “Show stars” overlay toggle is currently hidden. Instead, keep the control visible and surface a warning so the user understands that detection ran but found nothing, rather than the button silently disappearing.

  3. Default stretch before star detectionOpen question

    Decide whether a default stretch should be applied to the image before running star detection, and if so, which stretch. An open design question to resolve before settling on detector behavior.

  4. Default stretch for previewsOpen question

    The same question applied to previews: should a default stretch be applied before generating previews, and which one? To be decided alongside the star detection stretch decision.

  5. Make API keys preferences view larger

    The API Keys tab in the Preferences window (APIKeysPreferencesView) is too cramped. Enlarge the view so the API key fields have enough room to be read and edited comfortably.

  6. Verify whether MainMenu.xib is needed for a SwiftUI app

    The project still ships Base.lproj/MainMenu.xib, wired up through the NSMainNibFile key in Info.plist, even though the app uses the SwiftUI @main App lifecycle (FITScopeApp). Confirm whether this nib is actually required, and if not, remove the xib and its Info.plist reference to drop the dead AppKit scaffolding.

  7. Flesh out the Image menu

    The new Image menu (ImageCommands) currently exposes only the Plate Solve… action, while the other image actions live solely in the floating canvas toolbar (ImageToolbarView) with no menu equivalents or keyboard shortcuts. Add the rest of those actions to the menu so they are discoverable and keyboard-accessible: the zoom controls (Zoom In, Zoom Out, Actual Size at 100%, Fit to Window, Recenter) with standard shortcuts, and the canvas overlay toggles (such as “Show Stars”).

  8. Sidebar sort button doesn’t match the add button

    In the files sidebar header (FilesSidebarView), the sort control (the arrow.up.arrow.down menu) renders with a larger icon and a different color than the adjacent + (add files) button. The two should match: same icon size and same tint so the header controls look consistent.

  9. Overlays are laggy when resizing the window

    The canvas overlays drawn by CanvasOverlayLayer (stars, objects, frame, scale bar) lag behind the image while the window is being resized, instead of tracking the displayed image smoothly. Make the overlays redraw in step with the resize so they stay registered to the image without visible lag.

  10. Close the plate-solve window when its image is closed

    The plate-solve results live in a dedicated window (PlateSolveWindowView, the PlateSolveWindow WindowGroup) keyed to an open file’s ID. When the user closes an image, any plate-solve window opened for that image should be dismissed automatically, rather than being left behind referencing a file that is no longer open.

  11. Bring the open panel to front when reactivating the app

    The Open panel is presented modally (NSOpenPanel.runModal() in AppModel.runOpenPanel() and FilesSidebarView). When the panel is open and the app is sent to the background, reactivating the app should bring the open panel back to the front rather than leaving it buried or unreachable. Also consider Spaces support, so activating the app behaves sensibly when the panel lives on a different Space.

  12. Give overlays a consistent semi-transparent alpha

    The canvas overlays (CanvasOverlay implementations such as StarsOverlay, ObjectsOverlay, FrameOverlay and ScaleBarOverlay) draw with hard-coded, mostly opaque colours, so they can sit heavily on top of the image. Apply a sensible, consistent alpha across the overlays so they read as annotations layered over the image without fully obscuring what they mark.
